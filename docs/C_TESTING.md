# C Testing Guide for Whitespace Steganography

This document provides comprehensive guidance on testing the C implementation of the whitespace steganography project.

## 🧪 **Testing Approaches**

### 1. **Custom Test Framework** (Current)
- **File**: `c/test/test-c.c`
- **Features**: Comprehensive test suite with permutation testing
- **Usage**: `make test-c`

### 2. **Unity Test Framework** (Modern)
- **File**: `c/test/test_unity.c`
- **Features**: Modern C testing framework with assertions
- **Usage**: `make test-unity`

### 3. **Coverage Testing** (gcov)
- **File**: `c/test/test_gcov.c`
- **Features**: Code coverage analysis with gcov/lcov
- **Usage**: `make test-coverage`

### 4. **Shell Script Tests** (Integration)
- **File**: `c/test/run_tests.sh`
- **Features**: Integration tests with shell scripting
- **Usage**: `make test`

### 5. **Comprehensive Test Runner** (All-in-One)
- **File**: `c/test/run_all_tests.sh`
- **Features**: Runs all test suites with reporting
- **Usage**: `./c/test/run_all_tests.sh`

## 🛠 **Testing Frameworks**

### Unity Framework
Unity is a lightweight C testing framework that provides:
- Simple test macros
- Setup/teardown functions
- Test result reporting

**Installation**:
```bash
cd c
make install-unity
```

**Usage**:
```c
#include "unity.h"

void setUp(void) {
    // Setup before each test
}

void tearDown(void) {
    // Cleanup after each test
}

void test_function(void) {
    TEST_ASSERT_EQUAL(expected, actual);
}

int main(void) {
    UNITY_BEGIN();
    RUN_TEST(test_function);
    return UNITY_END();
}
```

### CMake Testing
For projects using CMake:
```bash
cd c/test
mkdir build && cd build
cmake ..
make

```

## 🐛 **Debugging Tests**

### Valgrind Integration
```bash
# Memory leak detection
valgrind --leak-check=full --error-exitcode=1 ./bin/test-c

# Address sanitizer
gcc -fsanitize=address -g test-c.c -o test-c
```

### GDB Debugging
```bash
gcc -g test-c.c -o test-c
gdb ./test-c
(gdb) break main
(gdb) run
```

## 🎯 **Best Practices**

### Test Organization
1. **Arrange**: Set up test data
2. **Act**: Execute function under test
3. **Assert**: Verify results

### Naming Conventions
- Test functions: `test_<function_name>_<scenario>`
- Test files: `test_<module>.c`
- Test data: Descriptive constants

### Error Handling
- Test both success and failure paths
- Verify error messages
- Test boundary conditions

### Performance Considerations
- Use appropriate test data sizes
- Measure execution time
- Monitor memory usage
